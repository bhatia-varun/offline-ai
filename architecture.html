    03 / Capabilities

    Who does what?

    The important boundary: LiteLLM owns text-model routing; FastAPI owns application behavior.

    01 · Generation

    Stable model contract

    general serves chat, RAG answers, and n8n summaries. agent handles tool selection. Both names are mapped by LiteLLM rather than hard-coded to a provider in FastAPI.

    02 · Retrieval

    Local, persistent RAG

    Markdown, text and PDF documents are chunked, embedded with Ollama nomic-embed-text, and stored in embedded Chroma. Generation of the grounded answer still uses LiteLLM.

    03 · Tools

    The app executes calls

    The model proposes calls; FastAPI dispatches a restricted calculator, deterministic weather, or two read-only MCP tools. MCP starts over stdio per call with a timeout and no public endpoint.

    04 · Voice input

    Independent local STT

    Record, upload or experimentally stream short audio chunks. FastAPI validates mono 16 kHz PCM WAV and runs cached MLX Whisper tiny.en in a killable worker. No LiteLLM or Ollama dependency.

    05 · Second client

    Open WebUI

    Optional browser-based plain chat using LiteLLM directly. It cannot access the application's FastAPI RAG, agent trace or transcription endpoints.

    06 · Automation

    n8n summary webhook

    A published local webhook posts to LiteLLM /v1/chat/completions using general and returns a one-sentence JSON summary. The key comes from its process environment.

    04 / Runtime & boundaries

    Run it with intent

    Lifecycle & ports

    • scripts/start.sh runs LiteLLM :4000, FastAPI :8000 and Streamlit :8501 on localhost; status.sh checks readiness; stop.sh stops tracked processes.
    • Ollama :11434 is managed separately. Open WebUI :3000 and n8n :5678 have independent start/stop scripts.
    • Optional n8n requires a compatible Node/n8n install and an imported, published workflow.

    Local state & safety

    • Documents are in rag/documents/; indexed vectors persist under rag/chroma/.
    • Optional client state lives under open-webui/data/ and n8n/data/. Logs, runtime data and .env are not meant to be committed.
    • MLX Whisper weights must be cached beforehand. Missing weights fail offline rather than downloading during a request.
    Accuracy notes. The current local YAML uses llama3.2:3b for both logical models, while hybrid YAML uses Ollama qwen3:14b first and Azure gpt-6-sol second. Azure fallback/tool calling are unverified and hybrid mode may incur charges. No TTS, image generation, or external weather API is implemented.
